# Feature Landscape: CRAN Package Requirements

**Domain:** R Package Submission to CRAN
**Researched:** 2026-01-22
**Confidence:** HIGH (based on official CRAN policies and documentation)

## Table Stakes

Features that are absolutely required for CRAN acceptance. Missing any = package rejection.

| Feature | Why Expected | Complexity | Notes |
|---------|--------------|------------|-------|
| **Pass R CMD check --as-cran (0 errors, 0 warnings)** | Automated requirement, failure = automatic rejection | High | Must test with current R-devel version |
| **Valid DESCRIPTION file** | Package metadata, required by R package structure | Low | Title, Description, Authors@R, License, Version all required |
| **DESCRIPTION Title field (proper format)** | First impression on CRAN landing page | Low | Title case, no package name, no trailing period, <65 chars |
| **DESCRIPTION Description field (proper format)** | Package purpose explanation | Low | Complete sentences, one paragraph, citations in author-year format with DOI/ISBN |
| **Copyright holder in Authors@R** | Legal requirement for CRAN to distribute | Low | Must include person with 'cph' role |
| **Standard open source license** | CRAN cannot review custom licenses | Low | Must be from CRAN license database |
| **Complete function documentation** | All exported functions must be documented | Medium | Every export needs @param, @returns, @examples |
| **Runnable examples** | Examples tested daily on CRAN infrastructure | Medium | Must execute or use proper conditioning (\donttest{}, not \dontrun{}) |
| **Valid NAMESPACE file** | Defines package API, required for R >= 2.14 | Low | Auto-generated by roxygen2 with @export tags |
| **S3 method registration** | Methods must be discoverable by generics | Low | Use @export on S3 methods (roxygen2 adds S3method() directive) |
| **Cross-platform compatibility** | Must work on ≥2 major R platforms (Linux, Windows, macOS) | Medium | Test with win-builder and local checks |
| **Source tarball format** | CRAN requires specific submission format | Low | Created by R CMD build, named PACKAGE_VERSION.tar.gz |
| **Examples runtime <5 seconds** | Tested daily across all CRAN packages | Medium | Use \donttest{} or subset data for longer examples |
| **No binary executables** | Security and portability requirement | N/A | Source packages only, no .exe/.dll/.so files |
| **Secure downloads only (HTTPS)** | CRAN security policy | Low | Any URLs must use https://, not http:// |
| **Valid URLs in documentation** | Broken links cause NOTEs | Low | Check with urlchecker::url_check() |
| **No package size >10MB** | CRAN infrastructure constraint | N/A | Source tarball preferably under 10MB |
| **Data + docs <5MB combined** | CRAN storage policy | N/A | Course notes inappropriate for CRAN |
| **Proper external dependency handling** | SystemRequirements must fail gracefully | Medium | For hdf5r: must work when HDF5 available, message when not |
| **Clean submission (no .git, etc.)** | Only relevant package files | Low | .Rbuildignore properly configured |

## Differentiators

Features that improve acceptance likelihood and CRAN maintainer goodwill. Not required, but valued.

| Feature | Value Proposition | Complexity | Notes |
|---------|-------------------|------------|-------|
| **NEWS.md file** | Documents changes between versions | Low | Standard format, rendered on pkgdown site |
| **cran-comments.md** | Communicates with CRAN maintainers | Low | Explains NOTEs, check results, revdep status |
| **No NOTEs from R CMD check** | Reduces human review burden | High | Each NOTE requires manual CRAN review |
| **Comprehensive test suite** | Demonstrates code quality | Medium | testthat tests in tests/testthat/ |
| **Package vignette** | Shows real-world usage | Medium | knitr/rmarkdown, adds VignetteBuilder to DESCRIPTION |
| **Authors with ORCID IDs** | Professional metadata | Low | Add comment = c(ORCID = "0000-...") in Authors@R |
| **Reverse dependency checks** | Shows responsibility for ecosystem | High | Only if package already on CRAN with dependents |
| **win-builder testing** | Windows platform validation | Low | Use devtools::check_win_devel() before submission |
| **R-hub testing** | Multi-platform validation | Low | Tests multiple R versions and platforms |
| **Minimal Suggests dependencies** | Reduces installation burden | N/A | Only suggest packages actually used |
| **Fast installation** | User experience | Medium | Avoid large compiled code if possible |
| **DOI citations in Description** | Professional references | Low | Format as <doi:10.prefix/suffix> |
| **ROR IDs for organizations** | Research organization metadata | Low | Research Organization Registry identifiers |
| **README with CRAN badge** | Shows package is on CRAN | Low | Update after acceptance |
| **pkgdown website** | Professional documentation site | Medium | Auto-renders NEWS.md and vignettes |
| **Informative error messages** | User experience | Low | Help users understand problems |
| **Graceful degradation** | Works when optional deps missing | Medium | Check for hdf5r with requireNamespace() |

## Anti-Features

Features to explicitly NOT include. Common mistakes that cause rejection or delays.

| Anti-Feature | Why Avoid | What to Do Instead |
|--------------|-----------|-------------------|
| **\dontrun{} for convenience** | Examples should be runnable | Use \donttest{} for slow examples, or create toy data |
| **"A package for..." in Description** | CRAN style violation | Start with action verb or direct description |
| **Package name in Title/Description start** | Redundant, CRAN style violation | Describe functionality, not package name |
| **Commented-out examples** | Shortcut, not acceptable | Write runnable examples or use proper conditioning |
| **Unquoted package names in Description** | CRAN style violation | Use single quotes: 'dplyr', 'ggplot2' |
| **Function names without parentheses** | CRAN style violation | Write foo() not foo in documentation |
| **Custom/non-standard license** | CRAN cannot review | Use GPL-3, MIT, Apache-2.0, etc. from CRAN list |
| **Email to individual CRAN members** | Violates submission protocol | Use CRAN-submissions@R-project.org only |
| **HTML email to CRAN** | Policy violation | Plain text ASCII only |
| **Frequent resubmissions (<1 month)** | Annoys maintainers | Wait 1-2 months unless fixing rejection issues |
| **Submitting without R-devel check** | Wastes CRAN time | Always check with current R-devel first |
| **Modifying R options without restoration** | Side effects policy violation | Use withr::local_options() or on.exit() |
| **Writing to user's home directory** | Security/privacy violation | Use tempdir() or ask permission with tools::R_user_dir() |
| **Unhandled internet failures** | CRAN infrastructure issues | Wrap internet code in tryCatch(), skip on failure |
| **sprintf() in compiled code** | Security risk | Use snprintf() instead |
| **Multi-threading >2 simultaneous** | CRAN resource policy | Limit parallel operations |
| **Terminating R process from C/C++** | Package cannot crash R | Handle errors gracefully |
| **Hard-coded absolute paths** | Portability violation | Use system.file(), tempdir(), relative paths |
| **Assuming development versions of dependencies** | Breaks CRAN checks | Only depend on released versions |
| **Large example runtimes (>10 seconds)** | CRAN infrastructure burden | Subset data or use \donttest{} |
| **Executable files in source package** | Security risk, not portable | Compile during installation |
| **Bundled third-party code without attribution** | Copyright violation | Preserve copyright notices, document in DESCRIPTION |
| **http:// URLs** | CRAN security policy | Use https:// only |
| **Breaking reverse dependencies without notice** | Ecosystem responsibility violation | Notify maintainers 2+ weeks ahead with patches |
| **Missing maintainer email confirmation** | Submission incomplete | Click email confirmation link |

## Feature Dependencies

For CRAN acceptance, the dependency chain is:

```
Core Package Structure
├── DESCRIPTION (proper format)
│   ├── Title (title case, <65 chars, no package name)
│   ├── Description (complete sentences, citations with DOI)
│   ├── Authors@R (with copyright holder 'cph')
│   ├── License (standard open source)
│   ├── Version (semantic versioning)
│   ├── Imports (strong dependencies from CRAN/Bioconductor)
│   ├── Suggests (optional dependencies: testthat, knitr, rmarkdown, hdf5r)
│   └── SystemRequirements (for hdf5r: HDF5 (>=1.8.13))
│
├── NAMESPACE (auto-generated)
│   ├── export() directives (from @export)
│   ├── S3method() directives (from @export on S3 methods)
│   └── import() directives (from @import/@importFrom)
│
├── R/ (source code)
│   ├── Documented functions (@param, @returns, @examples)
│   ├── S3 methods (@export for registration)
│   └── Internal functions (no @export)
│
├── man/ (documentation, auto-generated)
│   ├── Function help files (.Rd)
│   └── Package help file (package-level documentation)
│
├── tests/testthat/ (test suite)
│   ├── test-*.R files
│   └── testthat.R (test runner)
│
├── vignettes/ (optional but recommended)
│   └── *.Rmd files (requires knitr, rmarkdown in Suggests)
│
└── Submission files
    ├── NEWS.md (changelog)
    ├── cran-comments.md (submission notes, in .Rbuildignore)
    └── README.md (user-facing, updated post-acceptance)
```

**Key constraints for delarr with hdf5r:**
- hdf5r goes in Suggests (optional dependency)
- Code using hdf5r must check: `if (requireNamespace("hdf5r", quietly = TRUE))`
- Examples using hdf5r: `\donttest{}` or check availability
- Tests using hdf5r: `skip_if_not_installed("hdf5r")`
- Vignettes using hdf5r: Load conditionally with error handling

## MVP Recommendation for delarr CRAN Submission

### Phase 1: Mandatory Requirements (Must Complete)

1. **R CMD check compliance**
   - Fix all ERRORs and WARNINGs
   - Document and minimize NOTEs
   - Test with R-devel

2. **DESCRIPTION cleanup**
   - Verify Title (title case, concise, no "delarr" at start)
   - Verify Description (complete sentences, no "A package", cite methods if applicable)
   - Add copyright holder to Authors@R with 'cph' role
   - Verify license is standard

3. **Documentation audit**
   - Every exported function has @returns
   - Every exported function has runnable @examples
   - S3 methods have @export for registration
   - No \dontrun{} shortcuts

4. **Platform testing**
   - Local check on current platform
   - devtools::check_win_devel() for Windows
   - Consider R-hub for additional platforms

5. **Optional dependency handling (hdf5r)**
   - All hdf5r usage wrapped in requireNamespace() checks
   - Tests skip when hdf5r unavailable
   - Examples using hdf5r in \donttest{} or conditional
   - Graceful error messages when HDF5 unavailable

### Phase 2: Differentiators (Improve Acceptance)

1. **NEWS.md** - Document current version (even if "Initial CRAN release")
2. **cran-comments.md** - Explain check results, unavoidable NOTEs
3. **Vignette** - Already exists, verify it runs quickly
4. **Tests** - Already exists, verify coverage is reasonable

### Phase 3: Submission Process

1. Run final checks
2. Create submission tarball with R CMD build
3. Submit via devtools::submit_cran() or web form
4. Click email confirmation link
5. Monitor incoming checks

### Defer to Post-Acceptance

- pkgdown website setup
- CRAN badge in README
- Additional vignettes
- Performance optimizations
- Extended examples

## Special Considerations for delarr

### HDF5 Dependency Strategy

Since delarr has hdf5r as an optional dependency:

**Table Stakes:**
- hdf5r in Suggests field (not Imports)
- All hdf5r usage guarded: `if (requireNamespace("hdf5r", quietly = TRUE))`
- SystemRequirements: HDF5 (>=1.8.13) [if hdf5r functionality is central]
- Clear error messages when HDF5 functionality requested but unavailable

**Best Practice:**
```r
# In functions using hdf5r
use_hdf5 <- function(...) {
  if (!requireNamespace("hdf5r", quietly = TRUE)) {
    stop("hdf5r package required for HDF5 support. Install with: install.packages('hdf5r')")
  }
  # hdf5r code here
}

# In tests
test_that("hdf5 functionality works", {
  skip_if_not_installed("hdf5r")
  # test code
})

# In examples
#' @examples
#' \donttest{
#' # Requires hdf5r
#' if (requireNamespace("hdf5r", quietly = TRUE)) {
#'   # example code
#' }
#' }
```

### S3 Class Considerations

Since delarr has S3 class with methods:

**Table Stakes:**
- All S3 methods must have @export (registers with S3method())
- Standard generics (print, summary, etc.) must be imported if not from base
- Custom generics must be exported before their methods

**Best Practice:**
```r
#' @export
print.delarr <- function(x, ...) {
  # implementation
}

#' @export
`[.delarr` <- function(x, i, j, ...) {
  # implementation
}
```
